> Програмно-апаратна оптимізація лінійного ітераційного розв'язувача BiCGSTAB у гідродинамічному симуляторі OPM Flow шляхом впровадження графових топологій (CUDA Graphs), злиття ядер (Kernel Fusion) та просторового розпаралелення (Split).

## 🧠 Опис функціоналу

- ⚡ Асинхронне виконання послідовностей математичних операцій розв'язувача за допомогою **CUDA Graphs**, що усуває накладні витрати диспетчеризації (CPU Dispatch Overhead).
- 🧩 Програмне злиття обчислювальних ядер (**Kernel Fusion**) для мінімізації звернень до глобальної пам'яті (VRAM) та вирішення проблеми Memory-Bound.
- 🔀 Просторове розпаралелення незалежних векторних операцій (**Split**) по різних потокових мультипроцесорах.
- 👁️ Генерація `.dot` файлів для візуалізації топології згенерованих обчислювальних графів.

---

## 🧱 Опис основних оптимізованих сегментів

Алгоритм BiCGSTAB було декомпозовано на 6 незалежних графових топологій, серед яких:

| Граф / Сегмент | Призначення |
|----------------|-------------|
| `Граф 1` | Підготовка векторів та перша норма (оптимізовано через Kernel Fusion) |
| `Граф 3, 5` | "Важкі" обчислювальні вузли для множення розріджених матриць (cuSPARSE) |
| `Граф 4` | Паралельне оновлення векторів (оптимізовано через Split) |
| `Граф 6` | Фінальне оновлення та скалярний добуток (усунення мікросекундних затримок на шині PCIe) |

## ▶️ Як запустити проєкт "з нуля"

Цей проєкт є форком та розширенням оригінального симулятора **OPM Flow**. 
Оригінальний репозиторій проєкту: [OPM/opm-simulators](https://github.com/OPM/opm-simulators).

### 1. Встановлення інструментів та залежностей
Оскільки OPM є великим індустріальним симулятором, він вимагає специфічного набору залежностей (MPI, Boost, DUNE тощо).
🔗 **Офіційна інструкція зі збирання проєкту та встановлення залежностей**: [Building OPM from source](https://opm-project.org/?page_id=231)

В інструкції замість того щоб стягнути оригінальний репозиторій OPM simulator виконайте другий пункт з цього підрозділу.

Додаткова вимога для даної модифікації:
- Встановлений **CUDA Toolkit** (версія 10.0 або вище).

### 2. Клонування репозиторію та збірка

```bash
git clone https://github.com/Liloosh/opm-simulators.git
cd opm-simulators
mkdir build && cd build
cmake ..
make -j$(nproc)
```

## 🖱️ Інструкція для користувача (Запуск симуляцій)

Для активації впроваджених оптимізацій під час запуску симулятора на датасетах (наприклад, моделі **Norne**), необхідно передати спеціальний прапорець `--acceleration-mode`.

Ви можете комбінувати опції або використовувати їх окремо:

```bash
# Запуск з використанням усіх оптимізацій та генерацією візуалізації
flow параметри_моделі.DATA --acceleration-mode=cusparse-graph-viz-split-fuse
```

**Доступні опції прапорця:**
- `cusparse` — використання базових оптимізованих бібліотек.
- `graph` — інкапсуляція операцій у топології CUDA Graphs.
- `split` — просторове розпаралелення незалежних гілок.
- `fuse` — використання кастомних монолітних ядер (Kernel Fusion).
- `viz` — генерація файлів візуалізації графів.

### 👁️ Візуалізація графів
Якщо у прапорці вказано опцію `viz`, симулятор автоматично згенерує файли топології (наприклад, `grap1.dot`, `grap2.dot` тощо) у поточній директорії. 
Для їх перегляду у форматі зображення можна використати інструмент Graphviz:
```bash
dot -Tpng grap1.dot -o grap1.png
```

## 🧪 Проблеми і рішення

| Проблема              | Рішення                            |
|----------------------|------------------------------------|
| Збільшення загального часу роботи (на нових GPU) | На новітніх архітектурах (напр., L4 з 32MB L2 Cache) опція `fuse` може додавати надлишкові витрати на ініціалізацію. Рекомендується використовувати лише `graph`. |
| Програма не бачить GPU | Перевірте наявність драйверів NVIDIA та коректність змінних середоваща `PATH` для CUDA. |
